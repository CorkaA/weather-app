#### # Про БЭМ:

1. Один блок weather на всю страницу:  

```javascript
<main class="weather">
  <header class="weather__header">...</header>
  <div class="weather__content">
    <section class="weather__current">...</section>
    <section class="weather__forecast">...</section>
  </div>
  <div class="weather__slider"></div>
  <footer class="weather__footer"></footer>
</main>
```

Всё приложение — один блок weather, а элементы — weather__header, weather__content, weather__current, weather__forecast, weather__slider, weather__footer. Это нарушение БЭМ: шапка, поиск, текущая погода, прогноз, слайдер, футер — это самостоятельные блоки, а не элементы одного блока. По БЭМ должно быть:

`.header, .search, .current-weather, .forecast, .slider, .footer`

2. .`weather__search-btn--search / .weather__search-btn--clear` — модификаторы, но база одна: ``<button class="weather__search-btn weather__search-btn--search" aria-label="Найти">`` ``<button class="weather__search-btn weather__search-btn--clear" aria-label="Очистить">`` Имена --search и --clear — это разные элементы, а не модификаторы. Кнопка «Найти» и кнопка «Очистить» — разные сущности. По БЭМ:

`weather__search-btn (общие стили)` `weather__search-btn--search / --clear (разные иконки/поведение)` `Формально допустимо, но --search дублирует имя родителя (search). Лучше --submit / --reset или --primary / --secondary.`

3. .weather__input — элемент без блока-обёртки:   ``<div class="weather__search" id="search-container">`` ``<input class="weather__input" ...>`` weather__input — элемент блока weather, но логически он принадлежит weather__search. По БЭМ вложенность не отражается в имени, но имя weather__input слишком общее. Лучше search__input (если search — блок) или weather__search-input.
4. id="search-container", id="search-input", id="clear-btn" — не БЭМ ID в БЭМ не используются для стилизации, только для JS/якорей. Здесь они для JS — допустимо, но имена search-container, search-input, clear-btn не связаны с БЭМ-неймингом. Можно оставить, но для консистентности — weather-search, weather-input, weather-clear.
5. .weather__city-date-time — «склейка» трёх сущностей:    

```javascript
<div class="weather__city-date-time">
  <h2 class="weather__city">Москва</h2>
  <p class="weather__date">Суббота, 06 января</p>
  <p class="weather__time">11:29</p>
</div>
```

Имя weather__city-date-time смешивает три сущности через дефис. По БЭМ лучше:

`weather__location (обёртка)` `weather__city` `weather__date` `weather__time` или отдельный блок location.

2. **`<p class="weather__date">`Суббота, 06 января`</p**>` — дата без `<time>` html ``<p class="weather__date">`Суббота, 06 января`</p>`` ``<p class="weather__time">`11:29`</p>`` Дата и время должны быть в `<time datetime="...">`. Сейчас это просто `<p>` — семантически неверно
3. Кнопки без type:     ``<button class="weather__search-btn weather__search-btn--search" aria-label="Найти">`` ``<button class="weather__search-btn weather__search-btn--clear" aria-label="Очистить" id="clear-btn">`` Нет type="button" или type="submit". По умолчанию type="submit" — если обернуть в форму, кнопка «Очистить» будет отправлять форму. Нужно явно указать тип.

### БАГИ 🐞

#### Баги и недочёты

1. Неправильный CSS-селектор логотипа.weather__logo svg {
    flex-shrink: 0;
}В HTML класс `weather__logo` стоит непосредственно на SVG, поэтому селектор не сработает. Нужно:.weather__logo {
flex-shrink: 0;
}
2. Неправильный CSS-селектор иконки погоды.weather__icon svg {
    flex-shrink: 0;
}Если `weather__icon` — сам SVG-элемент, правило не сработает. Используй `.weather__icon`.
3. Вертикальное центрирование страницы может не работать У `body` есть `align-items: center`, но нет `min-height: 100vh`. Поэтому вертикальное центрирование относительно высоты окна не гарантировано.body {
    min-height: 100vh;
}Используй именно `min-height`, чтобы содержимое могло увеличивать страницу и появлялась прокрутка.
4. У поля поиска убран контур фокуса.weather__input {
    outline: none;
}При навигации клавиатурой пользователь может не видеть, что поле выбрано. Добавь стиль:.weather__input:focus-visible {
outline: 2px solid #F5F4F4;
}
5. Символы градусов позиционируются ненадёжно.weather__temp::after {
    content: '°';
position: absolute;
}Аналогичная проблема есть у `.weather__feels-like::after`. У родительских элементов нет подходящего позиционирования, поэтому символы могут оказаться не там, где ожидается. Надёжнее добавить знак градуса отдельным элементом в HTML.
6. Лишнее объявление `display`.weather__search-btn {
    display: flex;
/* ... */
display: none;
}Первое `display: flex` сразу переопределяется на `display: none`. Удали первое объявление — это не критический баг, а лишний код.

### РЕКОМЕНДАЦИИ 💡

Текст

Работа в целом выполнена хорошо, но есть несколько моментов, которые можно улучшить:

- **Исправить CSS-селекторы.** Селекторы `.weather__logo svg` и `.weather__icon svg` не сработают, если классы назначены непосредственно SVG-элементам. В таком случае нужно использовать `.weather__logo` и `.weather__icon`.
- **Вынести повторяющиеся значения в CSS-переменные.** Цвета, например `#F5F4F4` и `#DADADA`, используются несколько раз. Их можно объявить в `:root`, чтобы упростить поддержку и изменение стилей. [Документация MDN по CSS-переменным](https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_custom_properties).
- **Улучшить доступность поля поиска.** Вместо полного отключения контура через `outline: none` стоит добавить заметное состояние фокуса с помощью `:focus-visible`. Это поможет пользователям, которые перемещаются по странице клавиатурой. [Документация MDN по ](https://developer.mozilla.org/en-US/docs/Web/CSS/:focus-visible)`[:focus-visible](https://developer.mozilla.org/en-US/docs/Web/CSS/:focus-visible)`.
- **Упростить CSS.** В блоке `.weather__search-btn` свойство `display` объявлено дважды, причём первое значение переопределяется вторым. Лишнее объявление можно удалить.
- **Доработать структуру HTML.** Карточки прогноза пока пустые. Если они предусмотрены макетом, стоит добавить в них необходимые данные и иконки. Также нужно проверить, действительно ли нужны пустые блоки слайдера и подвала.
- **Проверить адаптацию содержимого по высоте.** Добавление `min-height: 100vh` для `body` поможет корректнее организовать вертикальное центрирование и прокрутку при недостаточной высоте окна.

В остальном структура классов понятная, БЭМ используется последовательно, а основные стили уже реализованы. Недочёты несложно исправить. Хорошая работа, продолжай в том же духе! 💪
